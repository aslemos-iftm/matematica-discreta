Funções recursivas

Todas as funções desta página vão de ℕ em ℕ. Parte-se de três funções tão simples que parecem não fazer nada e de umas poucas maneiras de combiná-las. Com elas se constrói tudo o que um computador calcula. A construção tem dois andares, e cada um corresponde a um comando que você já conhece: o for e o while.

Funções básicas

Três tijolos

São as funções recursivas primitivas de partida. Nenhuma delas calcula nada de interessante sozinha.

0

A constante zero

Uma função sem argumentos, de aridade zero, que devolve 0. É o único número dado de saída.

S(k) = k + 1

O sucessor

Soma um. É a única operação aritmética disponível. Somar, multiplicar e todo o resto terão de ser construídos a partir dela.

Pin(x₁, …, xₙ) = xᵢ

As projeções

Recebem n argumentos e devolvem o i-ésimo. Servem para escolher, entre vários valores disponíveis, aquele que interessa, e para descartar os outros — como, num programa, recuperar uma posição escolhida de um vetor.

É a mesma assinatura da aritmética de Peano: um zero e um sucessor. A diferença é de propósito. Na página de lógica de predicados, A3 a A6 eram axiomas sobre a soma e o produto. Aqui, soma e produto vão ser construídos — e o esquema de construção é o mesmo daqueles axiomas.

Operações

Compor e repetir

Duas operações produzem funções novas a partir de funções já geradas. As recursivas primitivas são as funções básicas, mais tudo o que se obtém delas aplicando essas operações um número finito de vezes.

Composição

Dada f, de aridade k, e g₁, …, gₖ, todas de aridade m:

h(x₁, …, xₘ) = f(g₁(x₁, …, xₘ), …, gₖ(x₁, …, xₘ))

Corresponde, em um programa, a calcular cada gᵢ e passar os resultados para f. Faz pensar em uma chamada de função com outras chamadas nos argumentos. Exemplo: S(S(P11(x))) soma dois.

Recursão primitiva

Dada f, de aridade k, e g, de aridade k + 2:

h(0, x₁, …, xₖ) = f(x₁, …, xₖ)
h(S(y), x₁, …, xₖ) = g(y, h(y, x₁, …, xₖ), x₁, …, xₖ)

O valor em S(y) se calcula a partir do valor em y. Para chegar a h(5, x₁, …, xₖ), passa-se por h(0, x₁, …, xₖ), h(1, x₁, …, xₖ), …, h(4, x₁, …, xₖ): cinco passos, nem mais nem menos.

A recursão primitiva é um for

Escreva o esquema como programa e ele vira um laço com número de voltas conhecido antes de começar:

definição

h(0, x₁, …, xₖ) = f(x₁, …, xₖ)
h(S(y), x₁, …, xₖ) = g(y, h(y, x₁, …, xₖ), x₁, …, xₖ)

programa 
h = f(x1, ..., xk);
for (i = 0; i < y; i++)
    h = g(i, h, x1, ..., xk);
return h;

Passe o cursor sobre uma parte da definição ou do programa para ver o que lhe corresponde.

O ponto decisivo está na linha do for: o laço dá exatamente y voltas, e o corpo não pode alterar nem i nem y. Por isso todo programa desse tipo termina, e toda função recursiva primitiva é total — tem valor para qualquer argumento.

Uma linguagem só com for. Meyer e Ritchie, em 1967, definiram a linguagem LOOP: variáveis, incremento, atribuição e laços com número de voltas fixado na entrada. Os programas LOOP calculam exatamente as funções recursivas primitivas. A profundidade de aninhamento dos laços mede o quanto a função pode crescer.







  
Minimização

  
Procurar sem saber até onde

  
A classe das funções μ-recursivas acrescenta um operador às anteriores. Ele não repete um número fixo de vezes: procura.


  

    
O operador μ

    
Dada uma função total f(y, x₁, …, xₖ), (μf)(x₁, …, xₖ) é o menor z tal que f(z, x₁, …, xₖ) = 0. Mais precisamente: f(0, x₁, …, xₖ), …, f(z − 1, x₁, …, xₖ) são todos maiores que zero, e f(z, x₁, …, xₖ) = 0.

    
A busca começa em zero e avança de um em um. Se nenhum y anula f, ela não termina — e a função não tem valor naquele ponto.

    

      

        definição
        
(μf)(x₁, …, xₖ) = o menor z tal que
  f(z, x₁, …, xₖ) = 0, sendo f(y, x₁, …, xₖ) > 0 para y < z

      

      

        programa

y = 0;
while (f(y, x1, ..., xk) != 0)
    y = y + 1;
return y;

      

    

    
Agora não há limite escrito em lugar nenhum. O while para quando acha — se achar. Por isso uma função μ-recursiva pode ser parcial: pode não ter valor para alguns argumentos.

Um único while basta. Kleene mostrou, em 1936, que toda função μ-recursiva pode ser escrita como uma função recursiva primitiva aplicada ao resultado de uma única minimização. Em termos de programa: “fors” à vontade e um só while, no lugar certo. Todo o risco de não terminar se concentra nele.







  
Totais e primitivas

  
Uma função total que nenhum for alcança

  
Toda função recursiva primitiva é total. A recíproca é falsa: há funções totais e computáveis que não são primitivas. O contraexemplo mais usado é a função de Ackermann.


  

    

      
A definição

      
A(0, n) = n + 1
A(m + 1, 0) = A(m, 1)
A(m + 1, n + 1) = A(m, A(m + 1, n))

      
Está bem definida: a cada chamada, ou m diminui, ou m fica igual e n diminui. A recursão sempre termina, e A é total.

      
Mas a terceira linha chama A dentro do argumento de A. O número de voltas de cada etapa só se conhece depois de calcular a etapa anterior. Não há como escrever isso com um número fixo de “fors” aninhados.

    

    

      
Cada linha, um for a mais

      

      

        
A(1, n) = n + 2soma

        
A(2, n) = 2n + 3produto

        
A(3, n) = 2n+3 − 3potência

        
A(4, n) = 22⋰ − 3torre de n + 3 dois

      

      
Para cada m fixo, n ↦ A(m, n) é recursiva primitiva. A função inteira não é: cresce mais depressa que qualquer função recursiva primitiva, porque cada valor de m exige mais um nível de laços.

Conjuntos

  
Gerar, aceitar, rejeitar

  
Com funções recursivas se fazem duas coisas com conjuntos: gerá-los, a partir de sementes e de funções que produzem novos elementos; e decidir se um objeto pertence a eles.


  

    

      
Um conjunto gerado

      
Semente: 1. Funções: x ↦ 2x e x ↦ 3x + 1. O conjunto é tudo o que se alcança a partir de 1 aplicando as duas funções quantas vezes se quiser.

      

        
        
      

      

        

        

      

      
Aqui a resposta é sempre sim ou não, porque as duas funções só aumentam: basta gerar tudo o que não passa do número procurado. O conjunto é recursivo — decidível.

    

    

      
Um while que ninguém sabe se para

      
Enquanto n ≠ 1: se n é par, divida por 2; senão, faça 3n + 1. É o problema de Collatz. Todos os números já testados chegam a 1. Ninguém provou que todos chegam.

      

        
        
      

      

        

        

        
      

      
Para perguntar se n leva a 1, basta executar: se levar, a resposta chega. Se não levasse, o programa rodaria para sempre, sem nunca responder não.

    

  


  
Aceitar sem rejeitar. Quando só se pode responder sim — esperando que a resposta chegue —, o conjunto é recursivamente enumerável. A diferença em relação ao conjunto recursivo é a diferença entre o for e o while. Por isso a teoria precisa incluir programas que, sempre ou em alguns casos, não terminam: eles não são acidentes. Sem a minimização, ficariam de fora funções que se calculam; com ela, entram junto as que não param.

  
E as funções totais? Ficam sem caracterização precisa. As recursivas primitivas são poucas — Ackermann fica de fora. As μ-recursivas são demais — incluem as parciais. Separar, entre estas, as que param sempre exigiria decidir se um programa termina, e Turing mostrou que isso não tem solução geral.
