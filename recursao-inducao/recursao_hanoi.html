A torre de Hanói

Três hastes, n discos de tamanhos diferentes, todos empilhados na primeira. O objetivo é levá-los para a terceira, movendo um disco por vez e sem nunca pôr um disco sobre outro menor. Esta página mostra duas soluções por recorrência e, para cada uma, um programa que é quase a própria definição.

O quebra-cabeça

Jogue antes de definir

Clique numa haste para pegar o disco do topo e em outra para soltá-lo. Cada movimento é anotado como uma tripla: número do movimento, haste de origem, haste de destino.

movimentos 0 mínimo 7
Por que 2ⁿ − 1? Para mover o maior disco, todos os outros precisam estar empilhados na haste auxiliar. Levá-los até lá custa o mesmo que resolver o problema com n − 1 discos; trazê-los de volta para cima do maior custa isso de novo. Então T(n) = 2·T(n − 1) + 1, com T(0) = 0 — e isso dá 2ⁿ − 1. Uma recorrência já aparece antes de qualquer programa.

Representação

A solução é um conjunto de triplas

Com as hastes A, B e C, e os discos começando em A, a solução para três discos é:

M(A, B, C, 3, 0) = { ⟨1, A, C⟩, ⟨2, A, B⟩, ⟨3, C, B⟩, ⟨4, A, C⟩, ⟨5, B, A⟩, ⟨6, B, C⟩, ⟨7, A, C⟩ }

Como cada tripla traz o seu número, a ordem em que se escrevem os elementos não importa: o conjunto já diz qual movimento vem antes. As duas propostas a seguir constroem esse mesmo conjunto por caminhos diferentes. A primeira faz recorrência sobre o número de discos; a segunda, sobre o número do movimento.

Primeira proposta

Recorrência sobre n

Sejam o, a, d ∈ {A, B, C}, distintas entre si — origem, auxiliar e destino —, e k ∈ ℕ, o número de movimentos já feitos antes desta etapa.

definição

M(o, a, d, 0, k) = { }

M(o, a, d, n, k) = (se n > 0)
  M(o, d, a, n − 1, k)
  ∪ { ⟨k + 2n−1, o, d⟩ }
  ∪ M(a, o, d, n − 1, k + 2n−1)

Prolog (o arquivo Hanoi.pl) 
m(O,A,D,0,K,[]).

m(O,A,D,N,K,R) :-
    N > 0,
    N1 is N-1,
    m(O,D,A,N1,K,R1),
    K2 is K+2^N1,
    m(A,O,D,N1,K2,R2),
    append(R1,[[K2,O,D]],R3),
    append(R3,R2,R).

Passe o cursor sobre as partes para ver a correspondência.

Lida em português: para mover n discos de o para d, mova os n − 1 de cima para a auxiliar, usando d como apoio; mova o maior de o para d — é o movimento de número k + 2n−1, porque os anteriores são os 2n−1 − 1 da primeira etapa; e traga os n − 1 da auxiliar para d, numerando a partir dali. O Prolog não acrescenta nada: o último argumento, R, é o resultado, e as duas chamadas a append fazem a união.

?- m(a, b, c, 3, 0, R).
R = [[1, a, c], [2, a, b], [3, c, b], [4, a, c], [5, b, a], [6, b, c], [7, a, c]]

Na consulta, as hastes vão em minúsculas: em Prolog, nome com maiúscula é variável.

Desdobrar a definição

Cada clique substitui todas as chamadas de M pela sua definição. Em rosa, chamadas ainda por resolver; em âmbar, movimentos já determinados.

Segunda proposta

Recorrência sobre k

Agora as hastes se chamam o, a e d — origem, auxiliar, destino; na notação anterior, A, B e C. A pergunta muda: em vez de “como resolver n discos?”, pergunta-se “qual é o movimento de número k?”.

Qual disco se move: d(k, n)

d(k, n) = n + 1, se k = 2ⁿ
d(k, n) = d(k − 2ⁿ, n − 1), se k > 2ⁿ
d(k, n) = d(k, n − 1), se k < 2ⁿ

d(k, n) é o disco movido no passo k, contando o menor como 1. A recursão vai tirando de k as potências de 2: o resultado é a posição do último 1 na escrita binária de k. O disco 1 se move nos passos ímpares, o disco 2 nos passos 2, 6, 10…, e o disco j a cada 2j passos.

Clique numa barra.

Para onde ele vai: soda e soad

Cada disco percorre as hastes sempre no mesmo sentido. Há dois sentidos possíveis:

o → d → a → osoda
o → a → d → osoad

Os discos com a mesma paridade de n seguem soda; os outros, soad. Com n = 3, os discos 1 e 3 vão de o direto para d; o disco 2 vai primeiro para a.

Daí f(k, n): a origem b do movimento k é onde o disco d(k, n) parou da última vez — o destino do seu movimento anterior, que foi o de número k − 2d(k,n). Se não houve movimento anterior, b = o. O destino é o próximo no ciclo.

Calcular o movimento k diretamente

Escolha n e k. A página segue a definição de f: volta pelos movimentos anteriores do mesmo disco até o primeiro, e então sobe de novo, aplicando o ciclo.

Definição e código

definição

solução = M(2ⁿ − 1)

M(0) = { }
M(k) = M(k − 1) ∪ { ⟨k, f(k, n)⟩ }

f(k, n) = ⟨⊥, o⟩, se k < 1
f(k, n) = ⟨b, s(b, k, n)⟩, se k ≥ 1,
  com b = y tal que f(k − 2d(k,n), n) = ⟨x, y⟩

s(b, k, n) = soda(b), se d(k, n) ≡ n (mod 2)
s(b, k, n) = soad(b), caso contrário

LISP (Hanoi.lsp, versão corrigida) 
(defun hanoi (n)
  (M (- (expt 2 n) 1) n))

(defun M (k n)
  (cond ((= k 0) nil)
        (t (append (M (- k 1) n)
                   (list (cons k (f k n)))))))

(defun f (k n)
  (cond ((< k 1) '(nil o))
        (t (let ((b (cadr
                      (f (- k (expt 2 (d k n))) n))))
             (list b (s b k n))))))

(defun s (b k n)
  (cond ((= (mod (d k n) 2) (mod n 2)) (S_oda b))
        (t (S_oad b))))

Passe o cursor sobre as partes para ver a correspondência.

> (hanoi 3)
((1 O D) (2 O A) (3 D A) (4 O D) (5 A O) (6 A D) (7 O D))

É a mesma sequência da primeira proposta, com o = A, a = B e d = C. Repare em cadr: devolve o segundo elemento de uma lista. É a projeção P22 da página anterior, que na definição aparece como “y tal que … = ⟨x, y⟩”.

M é um for. A segunda equação de M diz que M(k) se obtém de M(k − 1) acrescentando uma tripla. É, ao pé da letra, o esquema de recursão primitiva da página anterior: h(S(y)) = g(y, h(y)). Em programa, um laço de 1 a 2ⁿ − 1, com número de voltas conhecido antes de começar.

Comparação

Duas recorrências, duas formas

Sobre n: uma árvore

Cada chamada faz duas chamadas com n − 1. O desdobramento é uma árvore de altura n, e cada nó produz um movimento. Para saber qual é o movimento 20, é preciso montar a solução até ele.

É a recursão de quem divide o problema em partes do mesmo tipo: resolva o menor, e o maior vem junto.

Sobre k: uma linha

M percorre k de 1 até 2ⁿ − 1, um passo por vez, como um for. E cada movimento se calcula sozinho, voltando só pelos movimentos anteriores do mesmo disco — para o movimento 20, os de número 4 e 12.

É a recursão de quem encontrou uma regularidade: a sequência d(k) e os dois ciclos dizem tudo o que é preciso.

As duas são recursivas primitivas. Nenhuma precisa de while: em ambas, a quantidade de trabalho fica limitada antes de começar — n diminui a cada chamada numa, k diminui na outra. A diferença não está no poder de cálculo, e sim no que cada definição deixa ver do problema.
